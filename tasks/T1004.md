## Spécification (décidée, ne pas réinterpréter)
Banc **générique** qui remplace un fichier de test par jeu. Chaque carte de protection suivante le réutilise pour valider ses jeux.
1. `tests/catalogue.rs` (`#[ignore]`) : pour chaque jeu de `NG_GAMES` (liste séparée par des virgules ; si absent : tous les jeux de `ALL_CARTS` dont le zip existe) :
   - `load_machine(&cfg, jeu)` avec la config de `neogeo.toml` (même chargement que `mslug1.rs`) ;
   - 600 trames ; mêmes vérifications de santé que `mslug1.rs` (pas de double faute, SP en RAM) ;
   - image trame 600 : nombre de couleurs distinctes `>= 16` -> sinon état `NOIR` ;
   - si `tests-data/golden/<jeu>/f600.png` existe : diff en % comme `hwtests.rs` (seuil 2 %) ; idem trame 120 si `f120.png` existe ;
   - état par jeu : `ok` / `noir` / `diff <x>%` / `echec <message>` ; une panique d'un jeu est capturée (`catch_unwind`) et notée `echec`, le banc continue.
2. Écrit `target/catalogue-report.md` (tableau `jeu | état | diff120 | diff600 | secondes`) et affiche le même tableau (`--nocapture`).
3. Le test échoue seulement si un jeu est `echec`, ou (avec `NG_STRICT=1`) `noir` ou `diff > 2 %`.
4. `tools/mame_golden_batch.ps1 -Games a,b,c [-Out tests-data/golden]` : pour chaque jeu, appelle `tools/mame_golden.ps1 -Game <jeu> -Frames 120,600 -Out tests-data/golden/<jeu>` (démarrage à froid, nvram vierge, comme documenté dans STATE.md T707-T710). Aucune ROM n'est copiée.
