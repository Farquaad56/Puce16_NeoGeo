## Spécification (décidée, ne pas réinterpréter)
`pub fn mslug5_decrypt_68k(p:&mut [u8])` (taille exacte 0x800000, assert). **Règle d'adressage MAME->Rust** (DÉCISION) : `rom[X]` du C++ désigne l'octet MÉMOIRE de MAME (hôte x86 : mots 68000 stockés little-endian) ; notre `p` est big-endian 68000 ; donc `rom[X]` du C++ == `p[X ^ 1]`. Les copies `memcpy` de blocs alignés pairs sont identiques sur `p`. `BYTE_XOR_LE(i)` vaut `i` sur x86 (identité). Étapes (l.100-137) : (1) `p[i^1] ^= XOR1[i % 0x20]` pour i<0x100000 ; (2) `p[i^1] ^= XOR2[i % 0x20]` pour 0x100000<=i<0x800000 ; (3) pour i de 0x100000 à 0x800000 par pas de 4 : `rom16 = (p[(i+1)^1] as u16) | (p[(i+2)^1] as u16) << 8` ; `rom16 = bitswap::<16>(rom16, [15,14,13,12,10,11,8,9,6,7,4,5,3,2,1,0])` ; réécrire `p[(i+1)^1]=rom16&0xFF`, `p[(i+2)^1]=rom16>>8` ; (4) `buf=p.to_vec()` ; 16 blocs de 0x10000 : `ofst=(i&0xF0)+bitswap::<8>(i&0x0F,[7,6,5,4,1,0,3,2])` ; copie `p[i*0x10000..+0x10000] = buf[ofst*0x10000..]` ; puis pour i de 0x100000 à 0x800000 par 0x100 : `ofst=(i&0xF000FF)+((i&0x000F00)^0x00700)+(bitswap::<8>((i&0x0FF000)>>12,[5,4,7,6,1,0,3,2])<<12)` ; `p[i..i+0x100]=buf[ofst..ofst+0x100]` ; (5) `buf=p.to_vec()` ; `p[0x100000..0x200000]=buf[0x700000..0x800000]` ; `p[0x200000..0x800000]=buf[0x100000..0x700000]`. Tables XOR1/XOR2 (32 octets chacune) : recopiées du C++ (l.102-103).

## Règles de portage C++ -> Rust (cartes « port »)
- Traduire fonction par fonction, DANS L'ORDRE du fichier source, mêmes noms en snake_case (`instructionADD` -> `instruction_add`). Chaque appel `wait/idle/read/write/prefetch/step` du C++ reste un appel DANS LE MÊME ORDRE : c'est ce qui produit les cycles exacts. Ne pas « optimiser », ne pas fusionner, ne pas réordonner.
- Types : n1 -> bool, n4/n8 -> u8, n16 -> u16, n24/n32 -> u32, n64 -> u64, i8/i16/i32 signés. Les entiers sans signe de ares/ymfm sont modulo 2^N : utiliser `wrapping_add/sub/mul/shl` ou des masques explicites ; jamais d'arithmétique qui panique en debug.
- `template<u32 Size>` -> paramètre const générique `const SIZE: u32` (0=Byte, 1=Word, 2=Long) ; `uint` de ymfm -> u32.
- Conserver l'en-tête de licence (ares : ISC, voir ref/ares/LICENSE ; ymfm / MAME : BSD-3, voir ref/ymfm/LICENSE et l'en-tête `// license:BSD-3-Clause` des fichiers) en commentaire en tête de chaque fichier Rust porté, avec le nom du fichier source.
- Si le C++ utilise une construction sans équivalent évident : écrire la plus simple équivalente et noter `// PORT-NOTE:` ; ne pas changer le comportement.
