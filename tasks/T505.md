## Spécification (décidée, ne pas réinterpréter)
**Les vecteurs sont DÉJÀ générés par Claude depuis le vrai ymfm** (`tests-data/ym/*.bin`, versionnés ; pilote `tools/ymfm_golden.cpp`). Ne pas les régénérer. Cette carte écrit seulement le test Rust, qui rejoue les mêmes scénarios.
Format : 1000 échantillons × 3 voies i16 little-endian = 6000 octets ([FM gauche, FM droite, SSG]) ; `timers_status.bin` : 1000 octets, `read(0)` après chaque échantillon.
`common/mod.rs` : `struct TestIntf` implémentant `YmfmInterface` : `ym_time:u64` (en horloges YM, 1 échantillon = 144), `deadline:[Option<u64>;2]`, `busy_end:u64` ; `set_timer(t,d)` : `d<0` => `deadline[t]=None` sinon `Some(ym_time+d as u64)` ; `set_busy_end(c)` => `busy_end=ym_time+c` ; `is_busy()` => `ym_time<busy_end` ; `update_irq` mémorise le niveau ; `external_read(_,a)` (ADPCM-A et B) = `let h=a.wrapping_mul(0x9E3779B1); ((h ^ (h>>15)) & 0xFF) as u8`.
`run(writes:&[(u32 /*avant l'échantillon n, n>=1*/, u8 /*offset 0..3*/, u8 /*valeur*/)]) -> (Vec<[i16;3]>, Vec<u8>)` : `chip=Ym2610::new(intf)` puis `reset()` ; pour n de 1 à 1000 : (1) `ym_time=(n-1)*144` ; appliquer dans l'ordre toutes les écritures « avant n » via `write(offset,val)` ; (2) `ym_time=n*144` ; tant qu'un timer a une échéance ≤ n*144 : prendre le plus petit (le timer 0 en cas d'égalité), `ym_time=` son échéance, `deadline[t]=None`, `chip.engine_timer_expired(t)` (qui peut re-armer) ; puis `ym_time=n*144` ; (3) `generate(&mut o,1)`, stocker `o[0..3]` clampés en i16 ; (4) `status.push(read(0))`.
Scénarios : la liste exacte des écritures est dans `tools/ymfm_golden.cpp` (fonctions `lo(w,before,reg,val)` = offsets 0/1, `hi(...)` = offsets 2/3) : COPIER chaque scénario (silence, fm, ssg, adpcma, adpcmb, timers, mix) tel quel dans `scenarios()` du test, sans l'interpréter.
