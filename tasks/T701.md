## Spécification (décidée, ne pas réinterpréter)
`pub fn sfix_decrypt(c_rom:&[u8], fixed:&mut [u8])` : `tx_size = fixed.len()` ; `src = &c_rom[c_rom.len()-tx_size..]` ; pour i in 0..tx_size : `fixed[i] = src[(i & !0x1F) + ((i & 7) << 2) + ((!i & 8) >> 2) + ((i & 0x10) >> 4)]`.
`pub fn m1_address_scramble(address:u32, key:u16)->u32` (l.664-693) et `pub fn cmc50_m1_decrypt(m_crypt:&mut [u8], m:&mut [u8])` : `rom_size = 0x80000` ; `key` = somme 16 bits (modulo 2^16, octets additionnés un à un) des 0x10000 premiers octets de `m_crypt` ; `buffer[i] = m_crypt[m1_address_scramble(i,key)]` pour i in 0..0x80000 ; `m_crypt[..0x80000] = buffer` ; puis `m[0..0x10000] = m_crypt[0..0x10000]` ; `m[0x10000..0x90000] = m_crypt[0..0x80000]` (exigence : `m.len() >= 0x90000`). Port 1:1 depuis le C++ MAME (BSD-3, en-tête de licence à conserver) : mêmes opérations dans le même ordre, `bitswap<N>(v,b_{N-1},...,b_0)` => fonction Rust `bitswap_n` générique à écrire UNE fois (carte T700) : sortie bit k (k=N-1..0) = bit `args[N-1-k]` de l'entrée. Arithmétique `wrapping_*`/masques exacts.
Détail de `m1_address_scramble(address,key)` (identique au C++ l.664-693) : tableau `P1:[[u8;16];8]` copié du C++ (`p1`) ; `block=(address>>16)&7` ; `aux=(address&0xFFFF) as u16` ; `aux ^= bitswap::<16>(key as u32,[12,0,2,4,8,15,7,13,10,1,3,6,11,9,14,5]) as u16` ; `aux = bitswap::<16>(aux, [P1[block][15], P1[block][14], …, P1[block][0]])` (les 16 valeurs de la ligne `block` en ORDRE INVERSE : d'abord l'indice 15, dernier l'indice 0) ; `aux ^= M1_ADDRESS_0_7_XOR[(aux>>8)&0xFF]` ; `aux ^= (M1_ADDRESS_8_15_XOR[aux&0xFF] as u16)<<8` ; `aux = bitswap::<16>(aux,[7,15,14,6,5,13,12,4,11,3,10,2,9,1,8,0])` ; retour `(block<<16)|aux`. Les tables `M1_ADDRESS_0_7_XOR` et `M1_ADDRESS_8_15_XOR` (256 octets) sont copiées du C++ (fichier lu en entier dans la section « À lire »).

## Règles de portage C++ -> Rust (cartes « port »)
- Traduire fonction par fonction, DANS L'ORDRE du fichier source, mêmes noms en snake_case (`instructionADD` -> `instruction_add`). Chaque appel `wait/idle/read/write/prefetch/step` du C++ reste un appel DANS LE MÊME ORDRE : c'est ce qui produit les cycles exacts. Ne pas « optimiser », ne pas fusionner, ne pas réordonner.
- Types : n1 -> bool, n4/n8 -> u8, n16 -> u16, n24/n32 -> u32, n64 -> u64, i8/i16/i32 signés. Les entiers sans signe de ares/ymfm sont modulo 2^N : utiliser `wrapping_add/sub/mul/shl` ou des masques explicites ; jamais d'arithmétique qui panique en debug.
- `template<u32 Size>` -> paramètre const générique `const SIZE: u32` (0=Byte, 1=Word, 2=Long) ; `uint` de ymfm -> u32.
- Conserver l'en-tête de licence (ares : ISC, voir ref/ares/LICENSE ; ymfm / MAME : BSD-3, voir ref/ymfm/LICENSE et l'en-tête `// license:BSD-3-Clause` des fichiers) en commentaire en tête de chaque fichier Rust porté, avec le nom du fichier source.
- Si le C++ utilise une construction sans équivalent évident : écrire la plus simple équivalente et noter `// PORT-NOTE:` ; ne pas changer le comportement.
