## Spécification (décidée, ne pas réinterpréter)
Seuls les wait states DOCUMENTÉS sont implémentés : accès à la ROM cartouche P ($000080-$0FFFFF et $200000-$2FFFFF) : +0 (MAME ne modélise pas) ; accès aux ports/registres : +0. Donc cette carte pose le MÉCANISME : `fn bus_wait(addr:u32, write:bool)->u32` retournant 0 pour toutes les zones aujourd'hui, retourné par `Host68k::wait_clocks` (le CPU ajoute lui-même les horloges d'attente : +2 mclk par horloge). Ajouter dans docs/QUESTIONS.md « wait states réels non mesurables sans le hardware : table à remplir si une ROM de test hardware les révèle ». Test : `bus_wait` renvoie 0 partout ; un hook de test `set_wait_override` (cfg(test)) permet de vérifier que `now` avance du nombre configuré.

## Tests à écrire (valeurs exactes)
- Avec override de 2 horloges sur la zone RAM, `Host68k::wait_clocks(0x100000,false)==2` et un `MOVE.W $100000,D0` (`30 39 00 10 00 00`) dure 2 horloges (4 mclk) de plus qu'avec 0.
- Sans override : `wait_clocks` retourne 0 pour 0x000100, 0x100000, 0x300000, 0x3C0000, 0x400000, 0xC00000, 0xD00000.
