## Spécification (décidée, ne pas réinterpréter)
Les dépendances sont DÉJÀ déclarées dans `Cargo.toml` (`[workspace.dependencies]`, rev épinglées) et utilisées par `ng-core` (puce-m68k, puce-z80) et `ng-bus` (puce-z80) via `{ workspace = true }`. Cette carte : (1) `cargo fetch` puis `cargo build -p ng-core` doivent réussir ; (2) écrire le test de fumée `tests/cpu_crates.rs` qui fixe le contrat d'utilisation des deux crates (ne JAMAIS modifier ces crates : un manque se note dans `docs/QUESTIONS.md`).
API utilisée par tout le projet (voir `ref/cpu-crates/`) :
- 68000 : `use puce_m68k::{bus::Bus, cpu::Cpu, pins::Pins};` `Bus::{read(addr:u32,fc:u8,uds:bool,lds:bool)->u16, write(addr,fc,uds,lds,data:u16), wait_clocks(addr,write)->u8, ipl()->u8, int_ack(level)->Option<u8>, on_tick(Pins)}` ; `Cpu::{new, reset, step(&mut bus)->u32, step_clock(&mut bus)->Option<bool>, state()->CpuState, load_state, at_instruction_boundary, is_stopped, is_halted}`. `reset()` démarre la séquence de reset (40 horloges) ; elle se termine pendant les `step`/`step_clock` qui suivent. Une horloge = un appel de `on_tick` = 2 mclk. `Bus::read` est appelé à l'horloge 3 d'un cycle de bus, `Bus::write` à l'horloge 2 ; `wait_clocks` à l'horloge 0 (valeur = horloges d'attente ajoutées).
- Z80 : `use puce_z80::{Cpu, Pins};` `Cpu::{new, reset, tick(Pins)->Pins, at_instruction_boundary, step(&mut Bus)->u32}` ; champ public `cpu.regs` (a, f, b, c, …, pc, sp, iff1…). Un `tick` = un T-state = 6 mclk. Le projet utilise l'API broches (`tick`) : voir T305.
Test de fumée (valeurs mesurées sur ces révisions) :
1. 68000 : RAM 64 Kio miroir, vecteurs SSP=0x1000 (octets 00 00 10 00) PC=0x100 (00 00 01 00) ; programme à 0x100 : `30 3C 12 34` (MOVE.W #$1234,D0) `4E 72 27 00` (STOP #$2700). Boucle `step_clock` avec un compteur `ticks` incrémenté dans `on_tick` : première frontière d'instruction après **40** ticks (`state().pc == 0x104`, `state().ssp == 0x1000`), la suivante après **48** ticks (`state().d[0] == 0x1234`), ensuite `is_stopped()` et une frontière tous les 4 ticks.
2. 68000, attente : un programme `MOVE.W $200,D1` (`32 39 00 00 02 00`) dure 16 ticks sans attente et 18 ticks si `wait_clocks(0x200,false)` retourne 2.
3. Z80 (API `step`, pour fixer la référence) : `3E 01 87 76` (LD A,1 ; ADD A,A ; HALT) : 3 appels de `step` => `regs.a == 2` et 15 T-states au total.
